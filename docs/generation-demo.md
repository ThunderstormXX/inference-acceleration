# Наглядная генерация: обычный decode и MTP

[Анимация 0.25×](assets/mtp-0.25x.gif) · [Исходный темп 1×](assets/mtp-real-time.gif) · [Публичная запись событий](examples/mtp-trace.json) · [Происхождение записи](examples/mtp-trace.provenance.json)

Опубликованная запись очищена от личных путей и PID; временные метки, token IDs и события сохранены. Для рендера без загрузки модели можно передать `--trace docs/examples/mtp-trace.json`.

Демонстрация воспроизводит события двух последовательных запусков на одном Mac. Общий ноль времени — начало каждого запроса после загрузки и прогрева модели. Время prefill включено. Одновременный запуск двух моделей на одном GPU исказил бы сравнение из-за конкуренции за ресурсы, поэтому запись и воспроизведение разделены.

```bash
bash scripts/demo/trace.sh \
  --prompt-file configs/demos/seating-puzzle.txt \
  --enable-thinking --max-new-tokens 128 \
  --output artifacts/demos/mtp-race/trace.json

bash scripts/demo/render.sh \
  --trace artifacts/demos/mtp-race/trace.json \
  --output artifacts/demos/mtp-race
```

`scripts/demo/trace.{sh,py}` записывает реальные моменты доступности токенов. Слева обычный MLX-VLM, справа native MTP с блоком 3; целевая модель и входные token IDs одинаковые, sampling greedy. В финальной демонстрации thinking включён, как в исходном математическом бенчмарке: показаны первые 128 токенов рассуждения, а не законченное решение. Без `--enable-thinking` этот режим выключен. Веса не обучаются и не изменяются. Оба запуска используют свежий cache, прогрев и одинаковую политику wired memory / caffeinate.

Draft-событие появляется после готовности пакета предложений. Поэтому два предложения рисуются вместе, хотя сама MTP-голова вычисляет их последовательно. Золотой текст ещё не принят; после проверки в итоговый текст попадают только принятый префикс и токен target. Неверные предложения заменяются, а не маскируются правильным текстом. Зелёная подсветка подтверждённых токенов — визуальный эффект; она не задерживает следующие события. В версии записи 2 момент commit обозначает доступность выходных token IDs и постановку штатного обновления cache в очередь; он не заявлен как завершение всех GPU-операций с cache. Финальная синхронизация включена в полное время записи.

Блок проверки имеет форму одного запроса с несколькими позициями последовательности: опорный токен + до двух draft-токенов. Это не batch из двух независимых запросов.

`scripts/demo/render.{sh,py}` строит GIF только при полном совпадении записанных token IDs. Если в фиксированном бюджете появляется EOS, показ заканчивается на предшествующем ему тексте; соответствующее число токенов и время окончания указаны в `render-manifest.json`. Сами исходные события сохраняются полностью в `trace.json`. Текст не переписывается для анимации, временные шкалы не растягиваются отдельно для разных методов.

- `mtp-real-time.gif` — исходные интервалы событий, 1×. Паузы перед началом и после окончания нужны для просмотра и не входят в таймер запроса.
- `mtp-0.25x.gif` — те же события с одинаковым четырёхкратным замедлением обеих сторон; режим обозначен в кадре.
- `*-preview.png`, `*-final.png` — кадры для проверки вёрстки.
- `trace.json` — точный prompt, token IDs, предложения, результаты проверки и временные метки.
- `render-manifest.json` — параметры воспроизведения, хеш исходной записи и отображаемые времена.

Это иллюстрация одного запроса. Наблюдение за промежуточными предложениями требует чтения draft-токенов на CPU до проверки, его время включено в запись; результат не подменяет ранее сохранённые бенчмарки без такой инструментализации. Фактическое время завершения конкретного запроса зависит от машины и выбранного текста.

Для демонстрации выбран пример, где правая дорожка действительно приходит раньше. Это выбор иллюстрации, а не новая оценка среднего ускорения: остальные результаты тоже сохранены, временные метки не исправлялись.

| Промпт | Показано токенов | Baseline до конца текста | MTP до конца текста | Каталог |
|---|---:|---:|---:|---|
| История о маяке, тяжёлый наблюдатель v1 | 136 | 4.152 с | 4.902 с | `lighthouse-instrumented` |
| Круговорот воды, наблюдатель v2 | 130 | 4.000 с | 4.065 с | `water-cycle-instrumented` |
| Сумма 1…100, наблюдатель v2 | 182 | 5.569 с | 5.805 с | `gauss-instrumented` |
| Задача о местах в кинотеатре, thinking, v2 | 128 | **4.169 с** | **3.914 с** | `mtp-race` |

Исходные каталоги сохраняются локально в `artifacts/demos/` и не включены в Git; для выбранного примера опубликована очищенная запись событий по ссылке выше. В финальном примере полное совпадение **128/128 token IDs**, принято **80/95 draft-токенов (84.21%)**. Вывод фрагмента закончился на **0.256 с** раньше (отношение времён 1.065×). В GIF 0.25× разница визуально длится около 1.02 с, поскольку обе дорожки замедлены одинаково. Промпт полностью совпадает с четвёртым примером ранее измеренной выборки.


## Любая траектория из полного бенчмарка

Полная серия сохраняет реальные события **каждого** измеренного запроса, а не только средний tok/s. Запуск на всех 100 задачах с бюджетом 2048 выходных токенов:

```bash
bash scripts/benchmark/mtp_series.sh --count 100 --max-new-tokens 2048 --chunk-size 5 --label mtp-long2048
```

Порядок процессов чередуется: baseline→MTP для строк 0–4, MTP→baseline для 5–9 и так далее. Каждый процесс имеет отдельную загрузку модели и один полный прогрев; прогревы не входят в измеренные 100 запросов. Все процессы работают последовательно. Сводка и состояние находятся в `artifacts/series/mtp-long2048/manifest.json`; незавершённый запуск продолжается той же командой с `--resume`. Проверяются исходные хеши, параметры, версии и целостность уже выполненных блоков. При разряде ниже 20% следующий блок не начинается.

В каждой строке `samples.jsonl` сохранены исходный индекс датасета, текст ответа, token IDs, времена prefill/decode и `generation_trace`. В trace находятся время каждого наблюдаемого commit и все draft/verification события MTP: предложенные IDs, принятый префикс, отброшенный суффикс и время проверки. Сразу после запроса строка записывается с `flush`/`fsync`. Итоговые объединённые `samples.jsonl` сохраняют эти данные без потерь; manifest указывает их точные каталоги и исходные блоки.

После завершения серии можно выбрать **любой индекс 0…99** и создать GIF без повторной генерации:

```bash
bash scripts/demo/from_logs.sh --series artifacts/series/mtp-long2048 --index 42 --output artifacts/demos/sample-042
```

Это 43-я строка датасета, поскольку индексация начинается с нуля. Скрипт создаёт `trace.json`, GIF, контрольные PNG и `render-manifest.json`. Он загружает только локальный tokenizer для отображения текста; веса модели и GPU не нужны. Полный форматированный вход остаётся в token IDs и `metadata.decoded_input_text`; на экране показывается исходное условие задачи.

Управление воспроизведением:

```bash
# Одинаковое замедление обеих сторон, удобное для просмотра draft-пакетов
bash scripts/demo/from_logs.sh --series artifacts/series/mtp-long2048 --index 42 --rates 0.25 --fps 20

# Короткий ролик по первым 128 токенам; исходные логи остаются полными
bash scripts/demo/from_logs.sh --series artifacts/series/mtp-long2048 --index 42 --max-visible-tokens 128

# Только обогащённая запись для собственного визуализатора
bash scripts/demo/from_logs.sh --series artifacts/series/mtp-long2048 --index 42 --trace-only
```

Вместо `--series` можно передать `--baseline <каталог завершённого baseline>` и `--mtp <каталог завершённого MTP>`. Это работает и для отдельной завершённой пары блоков до конца всей серии. Для длинных ответов текст прокручивается; длинные GIF записываются потоком с ограниченным расходом памяти. Если output IDs различаются, визуализатор показывает обе фактические траектории с явным предупреждением вместо надписи о совпадении. В рендере старого trace такой режим включается через `scripts/demo/render.sh --allow-mismatch`.

**Методика записи:** обе временные шкалы начинаются с измеряемого prefill. Baseline отмечает уже существующие чтения токенов без новых GPU-синхронизаций. MTP дополнительно читает предложения на CPU до проверки; это наблюдение и запись временных меток входят в измеряемые фазы. Детокенизация для отображения и запись JSON находятся вне фаз. Скорости такой серии являются результатами **инструментированного** запуска и сравниваются с baseline, у которого запись тоже включена. Они не подменяют прежний бенчмарк без наблюдателя.

2048 — фиксированный вычислительный бюджет с игнорированием EOS; это не обещание законченного решения. В GIF показ заканчивается перед первым EOS. Публичный отчёт отдельно считает первые EOS и время их доступности, когда они встретились внутри бюджета. Полные локальные логи сохраняют и оставшиеся вычисленные токены; времени событий для старых запусков без `generation_trace` скрипт не выдумывает.
