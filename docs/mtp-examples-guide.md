# Каталог удачных и неудачных MTP-предсказаний

Начните с [60 разобранных примеров](examples/mtp-examples.md) или откройте [интерактивный каталог](examples/mtp-examples.html) локально в браузере. В нём **все 8409 полных пар**: 7621 из calibration100–109 и 788 из heldout110. Новая генерация не запускалась, порог не изменялся.

| Исход пары | Calibration | Held-out | Всего |
|---|---:|---:|---:|
| Оба токена приняты | 5936 | 562 | 6498 |
| Принят только первый | 976 | 135 | 1111 |
| Отказ уже на первом | 709 | 91 | 800 |

В этих полных парах первый токен принят в **7609/8409 = 90,49%** случаев; второй при условии принятого первого — **6498/7609 = 85,40%**. Доля принятых среди всех предложенных токенов — **14107/16818 = 83,88%**; знаменатель включает отброшенные вторые токены после первого отказа. Укороченные раунды на границе бюджета в эту таблицу не входят. Раунды внутри цепочки зависимы, поэтому 8409 пар не являются 8409 независимыми задачами.

Это совпадение с greedy target, а не оценка правильности ответа. Все examples получены из `confidence_collect`: оба предложения действительно проверялись. Непроверенные proposals confidence gate не используются как отрицательные labels.

## Что видно на примерах

- **Форматирование.** `c100-r493`: перенос строки принят, три пробела отвергнуты в пользу семи. `c106-r219`: один перенос заменён двумя. Такие различия не доказывают математическую ошибку.
- **Числа.** `c104-r439`: после `1/20 = 0` предложение `.` + `5`; точка принята, вместо `5` target выдал `0`, настоящее продолжение — `.05`. `c101-r546`: после `(3` запятая принята, `8` заменена на `6`.
- **Продолжение формулы.** `c107-r405`: закрывающие скобки приняты, но вместо окончания формулы target дописывает умножение на 100. Верный первый токен не гарантирует верной границы выражения.
- **Формулировки.** `c107-r313`: после `If` драфт предлагает ` so` + `,`, target начинает ` it`, продолжая `it's just ...`. По этому фрагменту нельзя объявить альтернативную фразу бессмысленной.
- **Confidence не равен acceptance.** `c109-r257`: score≈0,991, но первое предложение отвергнуто. `c106-r647`: score≈0,045, а оба токена приняты.
- **Локальные серии.** `c102-r49`…`c102-r53`: пять отказов на первом токене подряд. В той же цепочке `c102-r736`…`c102-r783`: 48 полностью принятых пар подряд. Это разные контексты, не повторные попытки одного запроса.

Наблюдения поддерживают разбор нескольких типов расхождений — layout, выбор формулировки, продолжение математической записи. Они пока не устанавливают внутреннюю причину ошибки головы и не ранжируют причины по частоте: тематическая подборка иллюстративна, автоматические tags пересекаются. Для оценки частот нужно заранее определить категории и размечать весь корпус; для проверки дообучения понадобятся новые непросмотренные задачи.

## Как пользоваться

По умолчанию показаны 60 выбранных карточек. Кнопка «Весь корпус» открывает весь корпус. Фильтруйте 2/2, 1/2 и 0/2, отдельно высокоуверенные отказы и низкоуверенные успехи; сочетайте цепочку, текстовый признак, диапазон score и поиск. У каждого примера есть ссылка вида `#c104-r439` и исходная задача.

Перед парой показаны 32 предыдущих generated token. Внутри карточки — два proposals, реально выданные токены с разделением accepted draft / target, `p1`, `p2`, произведение, ID и ещё 16 токенов настоящего продолжения. Зеленый — принят, красный — первое несовпадение, серый — отброшенный суффикс, синий — выданный target токен. Цвет сопровождается текстовой меткой.

После первого отказа второй proposal был построен на неверном продолжении; его нельзя независимо назвать ошибкой на настоящем контексте. Аналогично raw `target_token_ids` после первого mismatch обусловлены draft-префиксом. Например, для `c100-r25` такой вектор содержит ` Initial rest balls`, а реальная генерация — ` Initial percentage of blue balls`. Каталог берёт продолжение из `generated_token_ids`, сверенных с commit events.

## Пересобрать без inference

```bash
bash scripts/report/mtp_examples.sh
```

Скрипт проверяет frozen policy, SHA исходных логов, неизменность tokenizer assets, budgets и host evidence через существующий reader. Он загружает только локальный tokenizer, не веса и не GPU backend. Настройки ручной подборки: [configs/reports/mtp-examples.json](../configs/reports/mtp-examples.json). Пара `.sh`/`.py` вызывает классы `ExampleCorpus` и `ExampleAtlas`.

Выход: `docs/examples/mtp-examples.html`, `.md`, `.json.gz`, `.manifest.json`. HTML автономный: данные внутри, внешних запросов и зависимостей нет. Для просмотра после clone можно просто открыть HTML в браузере; GitHub отображает исходный HTML, поэтому Markdown-подборка доступна отдельно.

Если исходных benchmark logs нет, уже опубликованные HTML/Markdown работают самостоятельно. Для программного анализа можно распаковать [полный JSON](examples/mtp-examples.json.gz); модель для этого не нужна. Manifest фиксирует источники, selection, exporter, template и результаты экспорта.
